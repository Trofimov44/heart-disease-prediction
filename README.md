# Heart Disease Risk Prediction

ML-сервис для первичного скрининга сердечных заболеваний. Врачи вводят 13 клинических признаков → получают вероятность болезни + объяснение через SHAP.

**Стек:** Python, CatBoost, FastAPI, Streamlit, SHAP, Docker

**Результат:** Recall 0.86 для класса «болен» при пороге 0.40, AUC 0.88 (CV).

## 1. Описание задачи

Бинарная классификация: предсказание наличия заболевания сердца (condition = 0/1) по 13 клиническим признакам.

- **Целевая аудитория:** врачи-кардиологи для первичного скрининга
- **Метрика успеха:** Recall для класса «болен» ≥ 0.85 при пороге 0.40
- **Обоснование:** для скрининга критично не пропускать больных (FN дороже FP)

## 2. Данные

Датасет: [Heart Disease Cleveland UCI](https://www.kaggle.com/datasets/cherngs/heart-disease-cleveland-uci)

- 297 пациентов (реальные данные Cleveland Clinic Foundation)
- 13 клинических признаков
- Небольшой объём компенсируется stratified 5-fold CV
- Баланс классов: 54% здоровых / 46% больных

### Признаки

**Числовые:**
- `age` — возраст в годах
- `trestbps` — артериальное давление в покое (мм рт. ст.)
- `chol` — холестерин в сыворотке (мг/дл)
- `thalach` — максимальная ЧСС
- `oldpeak` — депрессия сегмента ST при нагрузке

**Категориальные:**
- `sex` — пол (1 = мужской, 0 = женский)
- `cp` — тип боли в груди (0–3)
- `fbs` — сахар натощак > 120 мг/дл (1 = да)
- `restecg` — ЭКГ в покое (0–2)
- `exang` — стенокардия при нагрузке (1 = да)
- `slope` — наклон сегмента ST (0–2)
- `ca` — количество поражённых сосудов (0–3)
- `thal` — талассемия (0–2)

**Целевая переменная:**
- `condition` — 0 = здоров, 1 = болезнь сердца

## 4. Feature Engineering

### 4.1 Созданные признаки

| Признак | Формула | Клиническая логика | r с target |
|---|---|---|---|
| `hr_reserve_ratio` | thalach / (220 - age) | % от макс. пульса для возраста | -0.37 |
| `oldpeak_is_zero` | oldpeak == 0 | наличие любой депрессии ST | -0.26 |
| `chol_per_age` | chol / age | накопление холестерина с возрастом | -0.10 |
| `chol_log` | log1p(chol) | нормализация скошенного распределения | +0.09 |

**Итог:** `hr_reserve_ratio` оказался важнее оригинального `thalach` в финальной модели (importance 6.9 vs 2.8).

### 4.2 Кодирование категориальных

- CatBoost — встроенный `cat_features`
- Random Forest — `pd.get_dummies(drop_first=True)`

## 5. Моделирование

### 5.1 Сравнение моделей

| Модель | CV AUC (5-fold) | Примечание |
|---|---|---|
| Dummy (baseline) | 0.500 | — |
| Logistic Regression | 0.887 ± 0.039 | — |
| **CatBoost** | **0.881 ± 0.051** | финальная модель |
| Random Forest | 0.864 ± 0.050 | — |

### 5.2 Обоснование выбора

- LR и CatBoost показали сопоставимый AUC (~0.88)
- Данные линейно разделимы → сложная модель не даёт прироста
- CatBoost выбран по дополнительным критериям:
  - Нативная работа с категориями (без one-hot)
  - Минимальный разброс между фолдами (std 0.051 vs 0.050 у RF)
  - Удобство объяснимости через SHAP

## 6. Финальная модель: CatBoost

### 6.1 Гиперпараметры
